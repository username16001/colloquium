# Подключение голосовой подготовки

Интерфейс подключён к отдельному Cloudflare Worker. GPT-6 Luna через RouterAI проверяет текст ответа, Groq Whisper расшифровывает аудио. Адрес сервера записан в `voice_config.json`, общие ключи хранятся в секретах Worker. Пользователям вводить ключи не нужно. Инструкция ниже нужна для собственного размещения проекта. GitHub Pages публикует только статические файлы и не хранит ключи.

## Подключение сервера

1. Создайте аккаунт на [Cloudflare](https://dash.cloudflare.com/sign-up), ключ [RouterAI](https://routerai.ru/docs/guides/overview/quickstart) для проверки и ключ [Groq](https://console.groq.com/keys) для расшифровки. Ключи вводятся в секреты сервера; не отправляйте их в чат и не добавляйте в Git.
2. Установите Node.js 22+ с npm, если его ещё нет. Из папки проекта выполните:

   ```powershell
   npx wrangler@4.149.0 login --device --browser=false --scopes account:read user:read workers_scripts:write
   npx wrangler@4.149.0 deploy
   npx wrangler@4.149.0 secret put GROQ_API_KEY
   npx wrangler@4.149.0 secret put ROUTERAI_API_KEY
   ```

   При входе откройте ссылку, выданную Wrangler, введите код и подтвердите доступ Cloudflare в своём браузере в течение пяти минут. Этот способ не требует соединения браузера с localhost. Право `workers_scripts:write` позволяет публиковать Worker. Команды `secret put` запросят ключи без добавления в файлы проекта. Можно добавить `GROQ_API_KEY` и `ROUTERAI_API_KEY` в Cloudflare → Workers & Pages → colloquium-voice → Settings → Variables and Secrets, тип **Secret**, затем нажать **Save and deploy**. Не используйте обычную текстовую переменную.
3. Скопируйте выданный адрес Worker, добавьте `/evaluate` и запишите в `voice_config.json`:

   ```json
   {"endpoint":"https://colloquium-voice.ВАШ-ПОДДОМЕН.workers.dev/evaluate","provider":"routerai"}
   ```

4. Пересоберите PWA (`py build_pwa.py`), проверьте настоящий запрос и опубликуйте изменения и GitHub Pages. После публикации пользователи применяют обновление через настройки. Никакого ключа от них не требуется.

Не публикуйте `.dev.vars`, `.env` или ключ в `voice_config.json`. Адрес сервера публичный; ключ — секретный. Worker использует текущий `questions.json`, включая исправленные эталоны и исключение дубля. После изменения базы переопубликуйте и Worker.

## GPT-6 Luna через RouterAI

В `wrangler.jsonc` заданы `GRADING_PROVIDER: "routerai"` и `ROUTERAI_MODEL: "openai/gpt-6-luna"`. В `voice_config.json` указан тот же `provider`, чтобы интерфейс правильно называл получателя текста. Для переключения существующего сервера сначала добавьте `ROUTERAI_API_KEY`, тип **Secret**, сохранив `GROQ_API_KEY`, затем опубликуйте Worker, проверьте настоящие ответы и опубликуйте пересобранную PWA.

Адаптер `backend/routerai.mjs` отправляет задание, эталон, объяснение и ответ студента в Chat Completions API. Используется обычная [GPT-6 Luna](https://routerai.ru/models/openai/gpt-6-luna) с ответом по строгой JSON Schema, `reasoning.effort: "low"`, `include_reasoning: false` и ограничением длины ответа. Рассуждения модели не передаются клиенту. При отказе, недостаточном балансе, усечённом или некорректном ответе оценка не записывается; автоматического перехода на другую модель нет. [Параметры RouterAI](https://routerai.ru/docs/guides/overview/parameters).

Прежние оценки Groq и новые оценки GPT-6 Luna различаются в истории и сохраняют баллы при экспорте/импорте. Подпись незавершённого уточнения продолжает использовать прежний секрет, поэтому смена модели не сбрасывает диалог. Расшифровка аудио остаётся в Groq, проверка текста — в RouterAI. Проверьте баланс и лимиты обоих сервисов: наличие ключа само по себе не подтверждает доступность модели.

## Альтернатива: Claude Haiku 5.5

Поддержка Claude подготовлена в `backend/claude.mjs`, но не включена. Для переключения с текущей модели:

1. Добавьте **ANTHROPIC_API_KEY**, тип **Secret**, в Cloudflare → Workers & Pages → colloquium-voice → Settings → Variables and Secrets. Альтернатива — `npx wrangler@4.149.0 secret put ANTHROPIC_API_KEY`. Не публикуйте значение ключа в файлах или переписке.
2. В `wrangler.jsonc` задайте `GRADING_PROVIDER: "anthropic"`; `CLAUDE_MODEL` уже равен `claude-haiku-5-5`. В `voice_config.json` установите `provider: "anthropic"`, чтобы перед отправкой текста интерфейс правильно называл получателя.
3. Опубликуйте Worker, выполните ручную проверку его настоящих ответов, пересоберите PWA и опубликуйте GitHub Pages. При ошибке API оценка не записывается; автоматического перехода на другого провайдера нет.

Claude получает текст задания, эталон, объяснение и ответ студента через Messages API. Шкала, зачёт от 7 и один уточняющий вопрос сохранены; ответы приходят по строгой JSON Schema. Haiku 5.5 используется с `output_config.effort: "low"` и без старых параметров `temperature`, `top_p`, `top_k`. Блоки thinking не передаются клиенту. [Модель](https://platform.claude.com/docs/en/models/haiku-5-5/overview), [формат ответа](https://platform.claude.com/docs/en/build-with-claude/structured-outputs), [переход на Haiku 5.5](https://platform.claude.com/docs/en/models/haiku-5-5/migration-guide).

**GROQ_API_KEY сохраняется для расшифровки аудио через Whisper.** Anthropic обрабатывает текст проверки; Groq — аудио. Старые оценки Groq и новые оценки Claude различаются в истории и сохраняют свои баллы при экспорте/импорте. Подпись незавершённого уточнения продолжает использовать прежний секрет, поэтому простая смена модели не сбрасывает диалог. Настройте бюджет и доступ к API в кабинете Anthropic; ключ не подтверждает наличие средств или доступность модели. Реальную проверку Claude нужно выполнить после добавления секрета.

## Проверка и ограничения

- Модель проверки по умолчанию — `openai/gpt-6-luna` через RouterAI, формат ответа — строгая JSON Schema. Выбор модели задаётся на сервере в `wrangler.jsonc`; пользователь не может заменить его параметрами запроса.
- Оценка 7–10 засчитывает ответ; 0–6 требует повторения. При пограничном первом ответе допускается один дополнительный вопрос. После него сохраняется одна итоговая оценка. Если пропустить уточнение, сохраняется первоначальная оценка. Отказ API, сети или микрофона не создаёт оценку.
- Оценка сверяет смысл ответа, а не совпадение слов. Для вопросов с кодом модель объясняет вывод и ошибки по эталону. Произвольный код студента не исполняется.
- В установленном приложении на iPhone/iPad запись идёт через `getUserMedia` и `MediaRecorder`. Нажмите «Ответить голосом», разрешите микрофон, произнесите ответ и нажмите «Остановить запись». Worker `/transcribe` передаёт аудио в Groq `whisper-large-v3-turbo` с языком `ru`. Используется тот же серверный секрет; дополнительный ключ не нужен. Предпочтительный формат — MP4, также поддерживается WebM. Ограничения записи — 90 секунд и 6 МиБ. [Распознавание аудио Groq](https://console.groq.com/docs/speech-to-text).
- В других браузерах сначала используется Web Speech API (`ru-RU`); речь может отправляться службе распознавания браузера. При отсутствии поддержки или сбое доступна запись аудио. Если браузер завершил распознавание без текста, приложение сообщает об этом и предлагает «Записать аудио». Всегда доступен ввод текста. [Web Speech API](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition).
- Перед проверкой текст можно исправить. Расшифровка сама по себе не создаёт оценку: отправка на проверку выполняется отдельной кнопкой. При сетевом сбое аудио остаётся только в памяти текущей страницы для «Повторить расшифровку»; перезагрузка, отмена, пауза или уход из тренировки удаляют его. Уход в фон останавливает запись и освобождает микрофон. Запрос разрешения микрофона сам по себе не считается уходом из тренировки.
- Черновики, диалог, оценки и история сохраняются на устройстве и включаются в экспорт прогресса; аудиозаписи в них не входят. Worker не ведёт журналов ответов и не сохраняет их в базе; аудио обрабатывается Groq, текст — RouterAI и провайдером модели по их политикам. Расшифровка и проверка требуют интернета. Не вводите личные секреты в ответ на учебный вопрос.
- Лимит Worker — 10 запросов за минуту с одного IP, общий для расшифровки и проверки. Один записанный и проверенный ответ обычно использует два запроса. Общая сеть может разделять этот лимит. Это ограничение частоты, а не общий денежный бюджет: CORS также не является авторизацией. Контролируйте расходы RouterAI и Groq перед публичным запуском. [Лимиты Cloudflare](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/), [лимиты расходов Groq](https://console.groq.com/docs/spend-limits).
- Продолжение диалога подписано сервером, привязано к вопросу и действует час. Если оно устарело или ключ изменился, начните новую тренировку. Результаты нейросети — учебная обратная связь; успешная проверка нескольких примеров не гарантирует качество всех будущих оценок.

## Ручная проверка опубликованного сервера

После добавления секретов и адреса выполните `py scripts/check_voice.py --expect-provider routerai` либо запустите в GitHub Actions **Check voice server manually → Run workflow**. Проверка отправляет несколько искусственных учебных ответов: верный пересказ, неверное утверждение, неполный ответ, уточнение при его запросе и ответ на вопрос с кодом. Она проверяет имя провайдера, расходует небольшую квоту RouterAI; ключ не требуется локально и не выводится. Это проверка подключения на небольшой выборке, а не независимая рецензия всех оценок нейросети.

По умолчанию между запросами выдерживается 35 секунд; при HTTP 429 допускается одна повторная попытка после ожидания. Отдельный сценарий можно выбрать в workflow или командой `py scripts/check_voice.py --case incomplete` (неполный ответ и уточнение) либо `--case code` (код). Лимиты Groq общие для организации, поэтому параллельная работа Playground и сайта тоже может исчерпать минутную квоту. [Документация лимитов Groq](https://console.groq.com/docs/rate-limits).

Для проверки расшифровки выберите сценарий **audio** в этом workflow. Он преобразует синтетический учебный WAV из `tests/fixtures/python-answer.wav` в AAC/M4A и отправляет файл в настоящий `/transcribe`. Локально можно выполнить `py scripts/check_voice.py --case audio` для WAV или добавить `--audio-file путь/к/учебному.m4a`. Сценарий проверяет только расшифровку и не ставит оценку. Тестовый файл содержит искусственно озвученную английскую фразу о Python; это проверка сервера и формата MP4, а не русского диктанта или физического микрофона iPhone. Не используйте для теста личные записи.

Если Groq возвращает 403, не заменяйте ключ наугад: причина может быть в разрешении модели или доступе API из сервера. Проверьте выбранную модель в Playground и доступ к ней на уровнях организации и проекта. Отдельные сообщения приложения различают эти два запрета; общий отказ 403 требует дополнительной проверки соединения. [Разрешения моделей Groq](https://console.groq.com/docs/model-permissions).

## Локальная проверка

Для проверки сборки Worker без публикации:

```powershell
npx wrangler@4.149.0 deploy --dry-run --outdir tmp-voice-worker
```

Для локального Worker скопируйте `.dev.vars.example` в `.dev.vars`, введите ключ только в `.dev.vars`, затем `npx wrangler@4.149.0 dev`. В `voice_config.json` временно укажите `http://127.0.0.1:8787/evaluate`, пересоберите приложение и запустите его на `http://127.0.0.1:8765/` по инструкции START_HERE. Перед публикацией верните адрес HTTPS. Тесты работают без ключа:

```powershell
py -m unittest discover -s . -p "test*.py"
npm test
```

Автоматические тесты используют заранее заданные ответы провайдера и имитацию событий речи, разрешений микрофона и MediaRecorder. Проверяются остановка, отмена, освобождение микрофона, повторная расшифровка и ошибки, но это не подтверждает работу микрофона на физическом iPhone или качество распознавания всех ответов.
