# Подключение голосовой подготовки

Интерфейс и сервер проверки готовы в исходниках. Для настоящих оценок нужны аккаунт Cloudflare, ключ Groq и адрес опубликованного Worker. Пока `voice_config.json` содержит пустой адрес, запись и ввод ответа доступны, проверка отключена. GitHub Pages публикует только статические файлы и не хранит ключ.

## Подключение сервера

1. Создайте аккаунт на [Cloudflare](https://dash.cloudflare.com/sign-up). Создайте отдельный ключ проекта в [Groq](https://console.groq.com/keys). Ключ вводится в секреты сервера; не отправляйте его в чат и не добавляйте в Git.
2. Установите Node.js 22+ с npm, если его ещё нет. Из папки проекта выполните:

   ```powershell
   npx wrangler@4.149.0 login
   npx wrangler@4.149.0 deploy
   npx wrangler@4.149.0 secret put GROQ_API_KEY
   ```

   При входе подтвердите доступ Cloudflare в своём браузере. Последняя команда запросит ключ без добавления в файлы проекта. Можно вместо неё добавить `GROQ_API_KEY` в Cloudflare → Workers & Pages → colloquium-voice → Settings → Variables and Secrets, тип **Secret**. Не используйте обычную текстовую переменную.
3. Скопируйте выданный адрес Worker, добавьте `/evaluate` и запишите в `voice_config.json`:

   ```json
   {"endpoint":"https://colloquium-voice.ВАШ-ПОДДОМЕН.workers.dev/evaluate"}
   ```

4. Пересоберите PWA (`py build_pwa.py`), проверьте настоящий запрос и опубликуйте изменения и GitHub Pages. После публикации пользователи применяют обновление через настройки. Никакого ключа от них не требуется.

Не публикуйте `.dev.vars`, `.env` или ключ в `voice_config.json`. Адрес сервера публичный; ключ — секретный. Worker использует текущий `questions.json`, включая исправленные эталоны и исключение дубля. После изменения базы переопубликуйте и Worker.

## Проверка и ограничения

- Модель по умолчанию — `openai/gpt-oss-120b` через Groq, формат ответа — строгая JSON Schema. Выбор модели задаётся в `wrangler.jsonc`. [Документация Groq](https://console.groq.com/docs/structured-outputs).
- Оценка 7–10 засчитывает ответ; 0–6 требует повторения. При пограничном первом ответе допускается один дополнительный вопрос. После него сохраняется одна итоговая оценка. Если пропустить уточнение, сохраняется первоначальная оценка. Отказ API, сети или микрофона не создаёт оценку.
- Оценка сверяет смысл ответа, а не совпадение слов. Для вопросов с кодом модель объясняет вывод и ошибки по эталону. Произвольный код студента не исполняется.
- Web Speech API используется по нажатию кнопки, русский язык `ru-RU`. Запись можно остановить, дописать или исправить расшифровку. Поддержка браузеров различается, есть ввод текста. Речь может отправляться службе распознавания браузера. Наш Worker получает только текст; голосовая проверка требует интернета. [Web Speech API](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition).
- Черновики, диалог, оценки и история сохраняются на устройстве и включаются в экспорт прогресса. Worker не ведёт журналов ответов и не сохраняет их в базе; текст обрабатывается Groq по политике провайдера. Не вводите личные секреты в ответ на учебный вопрос.
- Лимит Worker — 10 проверок за минуту с одного IP. Общая сеть может разделять этот лимит. Это ограничение частоты, а не общий денежный бюджет: CORS также не является авторизацией. Настройте лимит расходов проекта в Groq перед публичным запуском. [Лимиты Cloudflare](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/), [лимиты расходов Groq](https://console.groq.com/docs/spend-limits).
- Продолжение диалога подписано сервером, привязано к вопросу и действует час. Если оно устарело или ключ изменился, начните новую тренировку. Результаты нейросети — учебная обратная связь; качество на настоящих ответах нужно проверить после подключения ключа.

## Локальная проверка

Для проверки сборки Worker без публикации:

```powershell
npx wrangler@4.149.0 deploy --dry-run --outdir tmp-voice-worker
```

Для локального Worker скопируйте `.dev.vars.example` в `.dev.vars`, введите ключ только в `.dev.vars`, затем `npx wrangler@4.149.0 dev`. В `voice_config.json` временно укажите `http://127.0.0.1:8787/evaluate`, пересоберите приложение и запустите его на `http://127.0.0.1:8765/` по инструкции START_HERE. Перед публикацией верните адрес HTTPS. Тесты работают без ключа:

```powershell
py -m unittest discover -s . -p "test*.py"
npm test
```

Автоматические тесты используют заранее заданные ответы провайдера и имитацию событий речи; они не подтверждают качество реальной нейросети или работу микрофона на физическом iPhone.
