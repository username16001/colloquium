## Продолжение на Windows: самодостаточность условий

В папке `X:\colloquium` просмотрены условия и приложенный код всех **300 новых вопросов** на ссылки на отсутствующий пример или неописанный учебный интерфейс. При редактировании проверено равенство всех 138 исходных JSON-записей до и после правки; исходный префикс README сохранён байт в байт.

- **N08-002:** в условии явно описан Deck: внутренний список `_cards`, наследование от object, только `__init__`, `__len__` и `__getitem__`, не менее двух карт. Ответ не раскрыт в условии. В ответе и объяснении указано, что shuffle читает и записывает элементы на месте, а Deck недостаёт `__setitem__`. Наличие списка внутри не предоставляет запись по индексу внешнему объекту автоматически. Изменение на месте сверено с [официальной документацией random.shuffle](https://docs.python.org/3/library/random.html#random.shuffle), поведение проверено на реально исполняемом минимальном классе.
- **N03-018, N04-018:** указаны хешируемость значений для группировки и полный шаг алгоритма факториала вместе с областью входа.
- **N05-015, N05-018, N06-018:** определены контракт create_transformer, евклидово пространство для вывода расстояния и сигнатура Date(day, month, year).
- **N08-005, N08-013, N08-016:** явно объявлен TypeVar; описаны операции pick/load/inspect, обработка пустоты и предпосылки оценки стоимости. Из объяснения TypeVar убрано предположение о неуказанном bound.
- **N09-014, N09-015, N09-016, N09-019:** раскрыты генераторный конвейер, собственная функция repeat, алгоритм __iter__ с общей позицией и исходное условие остановки учебного Range.
- **N11-014, N11-015, N11-017, N11-018:** описаны общее хранилище и ключ Memoized, поведение count_calls/cache, начальное состояние счётчика и рекуррентное определение fib с условиями кэширования. Для Memoized добавлен конкретный пример неверного результата при совпадении ключей.

## Обнаруженные и исправленные ошибки

В коде исправлены потеря сравнений при HTML-рендеринге, нарушение форматирования/границ ответа, повтор одинакового вопроса на разных уровнях, зависимость загрузки базы от текущей папки и успешный exit status при ошибке запуска. При проверке рендерера также исправлено восстановление вложенных защищённых блоков кода в ответах.

Для **21 исходной записи** добавлены отдельные исправления/уточнения. Первоначальный текст сохранён в JSON, README и архиве:

- **O01-1-009** — В обычном .py-файле stdout пуст: вызова print нет. Последнее выражение в Jupyter отображается как [2, 4, 6].
- **O02-1-003** — Точный stdout — Hello Guest без запятой: print(f"Hello {name}"). Значение name равно "Guest" за счёт короткого замыкания.
- **O02-2-001** — flush передаёт буфер Python нижележащему потоку/ОС. Это не гарантия физической долговечности на диске: для неё требуются дополнительные средства ОС; close тоже выполняет сброс буфера.
- **O03-1-004** — Выражение создаёт set {0,4,16,36,64}, но в .py-файле без print не печатает его. В Jupyter показывается множество; порядок его представления не является гарантией языка.
- **O03-1-005** — Для хешируемости нужен успешно вычисляемый стабильный hash и согласованное равенство: равные объекты имеют одинаковый хеш. __hash__ может быть None или падать на вложенных значениях; одного наличия имени метода недостаточно.
- **O03-2-002** — keys(), values(), items() возвращают динамические dict_keys, dict_values, dict_items. Они отражают изменения словаря и не являются индексируемыми списками. Это тот же вопрос, что в сложной группе; исходный пустой ответ сохранён в архиве.
- **O03-2-004** — Надёжная проверка конкретного значения — hash(obj) с обработкой TypeError. isinstance(obj, Hashable) может быть True у кортежа с вложенным списком, но hash такого кортежа завершится ошибкой.
- **O03-3-003** — Размер динамически расширяется, но доступная память конечна: операция может вызвать MemoryError. Стратегия роста зависит от структуры и реализации; это не возможность вставлять буквально неограниченное число объектов.
- **O04-2-001** — Поверхностная копия дублирует внешний контейнер и сохраняет вложенные ссылки. Deepcopy рекурсивно воспроизводит граф, сохраняя внутренние общие ссылки и циклы; неизменяемые объекты могут переиспользоваться, а пользовательские классы могут определять политику копирования.
- **O04-2-005** — Последнее выражение обозначает b. В обычном .py-файле stdout пуст, поскольку print отсутствует; Jupyter показывает представление циклической структуры. Нельзя записывать буквальный [a, 30] как точный печатаемый результат.
- **O04-3-003** — В stdout ничего не печатается: необработанный TypeError возникает раньше print(t). Состояние t после ошибки — (1, 2, [3, 4, 5, 6]), потому что вложенный список уже изменился; сообщение исключения идёт в stderr.
- **O06-1-003** — __init__ инициализирует уже созданный экземпляр и должен возвращать None. Создание экземпляра обычно относится к __new__; называть __init__ конструктором можно лишь неформально, не смешивая стадии.
- **O06-1-005** — Атрибут класса найден через класс и может быть общим для экземпляров. Атрибут экземпляра хранится у данного объекта, но его значение не обязано быть уникальным: несколько полей могут ссылаться на один список.
- **O06-3-001** — Нельзя создать экземпляр класса с оставшимися нереализованными абстрактными методами. Само наследование от ABC не запрещает создание экземпляров полностью конкретного класса.
- **O06-3-002** — __slots__ задаёт слотовые поля экземпляра и обычно убирает его отдельный __dict__, экономя память. Он не заменяет словарь самого класса. Унаследованный __dict__ или наследник без slots могут сохранить возможность новых полей.
- **O07-2-001** — except Exception не ловит KeyboardInterrupt, SystemExit и GeneratorExit. Их перехватывают BaseException или голый except. Недостаток широкого Exception — смешение ожидаемых ошибок с программными багами и возможное сокрытие причины.
- **O08-2-003** — ABC задаёт интерфейс и может предоставлять готовые методы. Распознавание зависит от конкретного ABC: возможно наследование, регистрация или структурный __subclasshook, например у Sized. Это не полная проверка семантики.
- **O08-2-004** — ABC-проверка может учитывать наследование, регистрацию и структурные правила конкретного ABC. Утиный подход использует нужную операцию напрямую. Ни одно isinstance само по себе не доказывает корректность реализации.
- **O09-1-003** — Основной протокол — __iter__, возвращающий корректный iterator. Дополнительно поддерживается запасной перебор через __getitem__(0), __getitem__(1), ... до IndexError.
- **O09-1-006** — Итерируемый объект может быть iterator, а может им не быть. Каждый iterator является iterable; список iterable, но не iterator. Поэтому безусловный ответ «нет» неверен.
- **O09-2-010** — Генератор уже является разновидностью итератора. Класс-итератор выбирают для явного состояния и дополнительных методов; генератор — для последовательной логики yield. Независимый повторный обход требует нового состояния, а не просто иной формы реализации.

Спорные языковые детали сверены с [моделью данных Python](https://docs.python.org/3/reference/datamodel.html). Различие NumPy view/copy опирается на [официальное описание индексации](https://numpy.org/doc/stable/user/basics.indexing.html); вопросы о присваивании в pandas учитывают [Copy-on-Write и зависимость от версии/настроек](https://pandas.pydata.org/docs/user_guide/copy_on_write.html). Проверки `raises` и `approx` согласованы с [документацией pytest](https://docs.pytest.org/en/stable/how-to/assert.html). Основной источник содержания — предоставленные лекции, а документация использовалась для уточнения поведения.
