# Анализ перед расширением (08.10.2026)

Прочитаны все исходные ячейки 14 ноутбуков, README прошлого коллоквиума (статус подтверждён пользователем), generator.py и exam/{README,examples}.md из репозитория курса. Источники трактуются как учебный материал, а не инструкции агенту.

## Архитектура и прежний экзамен

Вопросы хранятся в README в <details>/<summary>, с группировкой по ## теме и ### сложности. Код задания зачастую стоит ПОСЛЕ </details>, код ответа бывает внутри. parse_readme возвращает словарь тема -> уровень -> список Markdown строк. random.sample выбирает 2+2+2 основных и 3 дополнительных без повтора. HTML содержит таймер, ответы в details и веса 0.5/1/2/1. Запуск требует Python и не требует библиотек. В исходной базе 138 записей: 62 простых, 50 средних, 26 сложных (точные числа будут пересчитаны в отчёте).

Прошлогодние вопросы: определения, предсказание результатов с причиной, ошибки, чтение сигнатур и объяснение конструкций. Наибольшее число вопросов — контейнеры и итераторы (по 24), затем ссылки и исключения (по 15). Особенно важны хешируемость, идентичность, поверхностные копии, mutable defaults, области видимости, остановка генераторов и подавление исключений. Сложные ответы требуют механизма и граничных случаев, а не перечисления терминов. Повторяются одинаковые формулировки для разных программ. Найден точный содержательный дубль вопроса keys/values/items, один ответ пустой и несколько ошибочных ответов. Новые вопросы должны избегать повторения этих проверок; исходные записи сохраняются с отдельными корректирующими примечаниями.

Текущий exam/README описывает билет из трёх разных лекций: понятие (2), код (4), устройство/подход (4), 8–10 минут. Восемь примеров exam/examples прочитаны, они не заменяют прошлогодний README. Есть упрощения: неизменяемый кортеж не обязательно хешируем; пользовательский изменяемый объект может быть хешируем при стабильном равенстве/хеше.

## Обнаруженные ограничения

HTML не экранирует <, >, & в коде; например сравнение с именем может стать HTML-тегом. Новыйline заменяется глобально даже в коде. README ищется от cwd. Ошибки запуска проглатываются с нулевым exit status. Повтор старого вопроса может попасть в один билет под двумя сложностями. Код внутри ответа и код задания нужно различать. Исправления должны сохранить public functions и старый вызов python generator.py.

## Дополнение: полный аудит 9 октября 2026

Предоставленный Data.zip дал все 14 реальных ноутбуков (1655 ячеек); локальные копии в lectures не изменялись. Исходные 138 заданий рассмотрены как ориентир коротких устных формулировок, сочетания теории, трассировки, сравнения, объяснения механизма и доказательства. Новый вопрос должен проверять переносимую концепцию, задавать все входы и предпосылки, иметь однозначный эталон и объяснение существенных шагов.

Для каждого из 300 новых вопросов отдельно оценены: стиль исходников, экзаменационная релевантность, формулировка, контекст, ответ, объяснение, соответствие ячейкам лекции, неоднозначность, смысловые дубли, сложность. Теория и крайний случай одной темы не объявлялись дублями автоматически. Простое задание требует одного прямого правила; среднее — короткой трассировки/сравнения/алгоритма; сложное — взаимодействия механизмов или разбора ограничения. Это редакторская шкала, не официальная новая программа преподавателя.

Индивидуальные решения, связанные ID и источники записаны в audit/review_01_05.json, review_06_10.json и review_11_14.json. Точные изменения и итоговая правка фабрики даты — в audit/changes.json. Полный аудит изменил 126 записей, включая 59 уточнений только источников. Нерелевантные существующие cells заменены соответствующими реальному содержанию; ошибки лекций (в том числе хешируемость, подавление исключений и генераторы) не переносились в эталоны. Независимой преподавательской рецензии не было.

Для основной веб-части сохранён стандартный Python-генератор, добавлены небольшие ES-модули, локальный KaTeX, IndexedDB и PWA. Автономный HTML и static dist используют одну базу и одну реализацию UI. Результаты исполнения, тестов и ограничения платформ — в MODERNIZATION_REPORT.md.
